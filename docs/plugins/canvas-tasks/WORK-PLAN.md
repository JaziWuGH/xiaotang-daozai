# 分工与排期：五个官方插件同时开工

本文按代码层次拆分全部工作。五个插件的逻辑层从第一天起同时开工，不用等画布。各任务的细节见对应的说明文件，本文只讲谁做什么、按什么顺序做。

## 一、代码分层

| 层 | 语言与位置 | 负责什么 | 对应任务 |
| --- | --- | --- | --- |
| 宿主后端 | Rust，`spike/`、`src/` | 规则和数据：清单与输出的解析、校验和上限；绑定求值和重绘时间；设置类型；资源包；存储导出 | A、B、C 的「后端」部分 |
| 宿主前端 | Rust/egui，`src/plugin_status_ui.rs` 等 | 画出来、动起来、能点：画布绘制、主题令牌、动画、点按、悬停、滚动区、岛仔节点、常驻小画布、新设置控件 | A、B、C 的「前端」部分 |
| 投稿校验 | Python，插件仓 `scripts/` | 让新插件能通过投稿检查 | P0 |
| 插件逻辑 | JavaScript，插件仓 `plugins/daozai.*/main.js` | 每个插件的数据、计算、状态切换、存储、提醒、常驻取值，用标准组件先出一个能用的版本 | P1–P5 第一阶段 |
| 插件画面 | JavaScript，同一个 `main.js` | 按设计稿生成画布描述 | P1–P5 第二阶段 |
| 数据 | JSON，插件包或 `src/` 数据文件 | 节假日数据、城市与时区对照表 | P5、C |

## 二、并行方式

```
第 1 周   A 画布核心          P0 投稿校验
          P1–P5 第一阶段：逻辑层 + 标准组件版（五个同时做）
第 2 周   B 实时与交互        C 常驻、字体包、设置补项
          P1–P5 继续逻辑层；A 合入后开始写静态画面
第 3 周   P1–P5 第二阶段：画面层（五个同时做），B、C 合入后补动画、点按、常驻小画布
第 4 周   联调、截图对稿、验收修改
```

建议人员：

- 一人负责宿主，顺序做 A → B → C，也可以 B 和 C 两人分做。
- 一人做 P0。
- 五个插件各一人，或者一人负责两三个。

插件之间互不依赖，可以同时提交。

## 三、插件两阶段

### 第一阶段：逻辑层（现在就能做）

只用现有 SDK，产出一个能装能用的「标准组件版」。

1. 清单：ID、能力、设置、刷新、联网来源、数据文件，按各插件说明填写。暂时不声明 `status.canvas`。
2. `main.js` 的逻辑部分，按「输入 → 状态 → 输出」拆成纯函数：
   - `computeState(input)`：从设置、存储、时间、来源数据算出这一刻的业务状态，比如工资的上班、休息、通关，或者金价的当前价、涨跌、区间点列。
   - `toStatus(state)`：用现有标准组件输出 `status`，作为没有画布时的显示。
   - `toPinned(state)`：常驻取值，先用现有 `text`、`value`、`icon` 写法。
   - `toCanvas(state)`：第二阶段再写，现在先返回 `null`。
3. 存储结构、设置迁移、提醒去重、`next_refresh_at`，全部在这一阶段做完。
4. 测试：
   - 在插件目录建 `fixtures/`，为每种状态放一份模拟输入 JSON。
   - 用 `daozai.exe --plugin-test plugin.json --input fixtures/xxx.json` 逐个跑，核对输出。
   - 把命令和期望结果写进插件目录的 `TESTING.md`。
5. 交付：装进岛仔能显示、能设置、能提醒的标准组件版，以及 fixtures 全部通过的记录。

### 第二阶段：画面层（A 合入后开始）

1. 实现 `toCanvas(state)`，按设计稿生成画布描述，清单加上 `status.canvas`。布局里放 `{"type":"canvas"}`，标准组件版的 `status` 保留，作为画布出错时的回退。
2. A 合入后先做静态画面；B 合入后补绑定、动画、点按、滚动、岛仔节点；C 合入后把常驻改成小画布，并换上新设置类型。
3. 每完成一屏，和 `ui/` 里的设计稿同尺寸截图对比，差异写进交付说明。

## 四、各插件的分层清单

| 插件 | 逻辑层要点 | 画面层要点 | 依赖的新能力 |
| --- | --- | --- | --- |
| P1 便签本 | 增删改、完成和撤销、置顶多条、搜索、常驻三种模式、专注事件、存储容量提示 | 纸堆、分组列表、滚动、切换动画、常驻色块 | A、B（点按、滚动、过渡）、C（多行输入、导出） |
| P2 现货金价 | 两个 xaus 来源、两种单位各存点列、区间降采样、提醒跨线去重、`fx_stale`、涨跌配色 | 主价格、涨跌块、面积图、提醒线、悬停读数、单位和区间切换 | A、B（点按、`tips`、过渡）、C（常驻小画布） |
| P3 实时工资 | 工作日数、多段休息、计薪规则、状态切换时刻、跨午夜、常驻三种显示 | 计价器翻动、经验条、岛仔节点、休息和通关动画 | A、B（counter、progress、roll、loop、pet、burst）、C（常驻小画布） |
| P4 世界时钟 | 最多 10 个城市、时区偏移和夏令时、昨天/今天/明天、色条区段计算 | 表盘、日夜换色、24 小时色条、现在线 | A、B（clock_angle、daylight、progress）、C（timezone 设置、常驻小画布） |
| P5 日子 | 节假日数据与自己的日子合并排序、三种类型的天数、筛选、模板替换、整百天提醒 | 手撕日历、撕页动画、车票滚动列表、常驻图标和文字 | A、B（过渡、滚动、点按）、C（icon、color 设置、常驻小画布） |

## 五、验收节点

| 节点 | 交给谁 | 验收什么 |
| --- | --- | --- |
| A 完成 | 宿主负责人 | 演示插件静态画面、上限校验、测试 |
| P0 完成 | P0 负责人 | 投稿脚本测试 |
| 五个插件第一阶段完成 | 各插件负责人 | 标准组件版能装能用，fixtures 全通过 |
| B、C 完成 | 宿主负责人 | 演示插件会动、能点；常驻小画布；字体包；设置补项 |
| 五个插件第二阶段完成 | 各插件负责人 | 截图对稿、帧率记录、全部测试 |

每个节点交付时，按 README 的「交付时附上」提供材料，由小唐转给验收方。
