# 岛仔插件 SDK v1 需求覆盖与待决定方案

2026-11-18 · 评审基线 `plugin-sdk-spike@dcf54db`

**建议第一轮用 QuickJS 做通本地插件的安装、启停、重启和卸载。** 验收的关键是作者能复制倒计时包、换一个 ID 和标题，再装成第二个插件。两个插件应各自有设置、开关和数据。现有样例按引擎选定倒计时文件，宿主直接绘制倒计时文案，重启读回成功只能证明这个样例可运行。这是从技术验证走到通用 SDK 最先要跨过的一步。[加载实现](../../spike/mod.rs) · [卡片实现](../../spike/ui.rs) · [测量结果](runtime-spike.md)

## 需求覆盖情况

“已实测”指 Windows 验证程序已运行相应步骤。“草案”指已有接口或交互约定，仍需宿主实现。“缺接口”指按当前清单和示例，作者无法完成该步骤。浏览器原型可以核对入口和文案，真实进程的启停、权限和数据恢复要在岛仔里另验。需求来源见[功能建议模板](https://github.com/Renly1994/xiaotang-daozai/blob/main/.github/ISSUE_TEMPLATE/feature_request.yml)、[拓竹作者的样例](https://github.com/Renly1994/xiaotang-daozai/issues/138#issuecomment-6919288370)、[SDK 草案](sdk-v1-design.md)和[插件清单格式](sdk-v1.schema.json)。

| 用户需求 | 草案或样例已覆盖 | 作者接入时还缺什么 |
| --- | --- | --- |
| 新增 AI 额度服务 | 草案有额度来源、周期和剩余比例，沿用额度面板 | 用真实来源验证授权、失效后重新登录，以及停用时只撤回本来源 |
| 日程、农历、纪念日 | 草案支持提供日程记录，纪念日可以同时有自己的列表和固定卡 | “给某天加农历标签”与“新增一条日程”效果不同，前者缺少日期标注的公开约定。还要实测关日程仅撤回跨模块输出 |
| 邮箱、聊天软件 | 未读数可用草案中的卡片，单次提示可用通知 | 写入内置收件箱或消息列表缺来源接口。若要开放，先明确消息 ID、更新、撤回和已读状态由谁维护 |
| 查看打印机或其他设备 | 草案有临时卡和独立模块。作者已在自己的分支接通本机监控 | 独立页缺少可组合布局示例。本机监控提供只读 HTTP，而当前 SDK 的网络规则拒绝本机地址，真实接入需另定授权 |
| 倒计时、从网站取数 | 已实测倒计时配置、显示、存储和重启读回。公开网站可按草案声明 HTTPS 域名 | 倒计时缺按清单装卸的完整验证。网站请求只测过模拟传输，需用真实接口验证。需要登录的网站还缺作者可调用的凭据使用约定 |
| 皮肤、表情、图标 | 草案允许无代码资源包，用户从原选择器切换 | 资源路径能写进清单，具体可替换部位、表情帧与缺失素材回退还需一个可安装的样例 |
| 歌词、天气、待办来源 | 歌词有曲目标识和时间字段。天气和待办已有设置归属可选 | 实时歌词需验证切歌时清除过期数据。清单尚无天气或待办来源能力，进入原面板需要对应的数据约定 |
| 专注日志、快捷操作 | 草案有专注结束事件，原型覆盖手动和自动记录 | 验证同一事件只记录一次、关闭自动记录仍可手动使用、停用后迟到的回调不写入 |
| 便签等独立工具 | 草案有列表、详情、编辑表单和私有存储 | 用实际数据验证编辑、固定、卸载保留和重装认领。用户想专门查看完整状态时，也需要有进入独立页的途径 |
| 改进内置体验 | 例如调整剪贴板历史条数，由本体拥有设置和执行逻辑 | 放在原设置中即可。如插件要提供新的剪贴板来源，再单独讨论它能读写哪些内容 |

## 第一轮的四个验收场景

| 场景与现状 | 用户或作者怎样操作 | 通过条件 |
| --- | --- | --- |
| 发薪倒计时 · 样例部分已实测，首个完整实现 | 本地选包加载，在「我的插件」点“前往设置”，去「待办与置物」改日期。停用后重启，再启用。分别试卸载保留和删除后重装 | 改日期后岛卡更新。停用后刷新调用数停止增长，重启仍停用。启用恢复原日期。卸载后入口和卡片撤下，同身份重装按上一次的保留选择恢复或使用默认值 |
| 换肤包 · 交互已有原型 | 从奶油切到插件皮肤，把胶囊改为刘海，先切回内置皮肤，再试停用正在使用的插件皮肤 | 已安装的皮肤可随时切换。停用后显示奶油＋刘海，包内配色随各自皮肤保存 |
| 纪念日 · 开关模型已有推演 | 建一条纪念日，同时固定倒数、显示在日历。先关日程，再关纪念日，重开时核对原选择 | 关日程只撤下日历记录。关纪念日时「我的插件」同步显示停用，入口和全部输出撤下。重启用后原文、日期、固定选择均可找回 |
| 拓竹 · 作者已有参考实现，SDK 接入待验 | 先用模拟数据让作者加一个“预计完成时间”，再用已授权的本机监控验证正常、暂停告警、设备离线、监控没启动和停用 | 第一步只更新插件包，岛仔无需重新编译。第二步能区分旧数据与当前值，依赖离线时降低重试频率，设备告警显示给用户。关闭模块后岛仔停止读取，用户原有监控程序独立运行 |

四项共同遵守已讨论的入口规则。参数在唯一归属设置页调整，「我的插件」统一提供启停、卸载和跳转。页面管理负责模块启停。倒计时挂在已有模块，仅用插件开关就能单独停用它。

## 需要决定的三件事

**1. 下一轮用哪种运行环境？建议先选 QuickJS 验收本地插件。** 作者改日期算法后可直接加载脚本，用户继续从待办设置改发薪日期。采用现有 Rust 逻辑较多的作者也可从 WASM 获益。实测中两者加载十个实例的热中位数分别为 12.28 和 4.12 毫秒，程序分别增加 0.152 和 1.163 MiB。双环境首发需要维护两套执行与兼容回归。当前只需决定倒计时完整流程用哪套，公开支持哪些语言可等作者试接后定。[完整实测](runtime-spike.md)

**2. 作者能自己设计到什么程度？建议先试“作者组合布局，岛仔渲染”。** 原额度页由作者提供数据，岛仔沿用原面板。独立页允许作者决定字段、顺序、分组和点击动作。例如作者把预计完成时间放到进度下方，用户换皮肤或缩放后仍能看清并点击。固定模板容易起步，但每次超出模板都需要岛仔新增样式。开放自由绘制能容纳特殊视觉，也需要作者处理主题、缩放和命中区域。先用拓竹的只读页和便签的编辑页各试一次布局组合，再定公开控件范围。

**3. 是否允许插件读取已安装软件提供的状态？建议单独试验“用户指定应用、只读授权”。** 一条路是沿用用户选文件的草案，让监控工具导出状态。另一条是适配已有的本机只读服务，拓竹作者可复用现成监控。第二条需由岛仔核对服务身份、处理端口变化及本机代理，在安装前说明依赖，首次启用时写明“允许读取拓竹打印监控的状态”。撤权后停止读取。该选择影响真实设备接入，倒计时和模拟打印页可独立验收。

## 本地安装流程的交付边界

首个可试用版本应能从开发者模式选择本地包、读取清单、注册设置和岛卡，再从「我的插件」启停或卸载。验收时用两个不同 ID 的倒计时包分别改日期和停用，确认彼此独立。还要在上级模块关闭后重开，确认此前手动停用的插件保持停用。

等这条流程可试用，再依据实测区分稳定与实验能力。旧包兼容期限、市场审核和签名分发可在对外发布前决定，首轮本地安装验收使用本地样例包。
