蓝牙电量没有一个万能接口。

岛仔适合采用「Windows 已有电量 + 标准 BLE 电量 + 按设备补充协议」的组合。高星项目能提供成熟的读取与状态处理思路，但跨品牌适配必须落实到具体型号和连接方式。

星数与最近推送日期来自 GitHub 当日仓库元数据；覆盖范围根据 README 和所列源码核验。源码存在不代表本机已完成硬件验证，推送日期也不等于稳定版发布日期。

源码里的关键结论

通用 BLE：读取一次，再订阅变化

标准电池服务使用 0x180F，电量特征使用 0x2A19。先确认设备确实提供服务，再读取 0–100 的值；支持 Notify/Indicate 才订阅。不支持通知时使用低频读取。Bleak 的 WinRT 后端还处理服务缓存、会话关闭、连接失败和回调清理。Windows 官方文档明确 GATT 访问可能等待较长时间，不能让它阻塞界面。

来源：Bleak · WinRT client、btleplug · Windows peripheral、BLE Battery Service 实现、Microsoft GATT Client。

罗技：同一个品牌也有多套电量语义

Solaar 的 get_battery 探测多个能力，分别处理 battery status、unified battery、voltage 和 Centurion。部分结果是百分比，部分是粗分档，部分由电压估算。岛仔的数据模型应保留「精确百分比 / 约值 / 档位」区别，不能全部转换成看似精确的百分数。

来源：hidpp20.py · get_battery / decipher_battery_* / estimate_battery_level_percentage。

真无线耳机：左右耳、盒子、充电状态分开建模

GalaxyBudsClient 的 StatusUpdateDecoder 对不同代际分支，分别读取 BatteryL、BatteryR、BatteryCase；充电位受设备能力限制。OpenPods 从 Apple 广播半字节提取分档电量，并处理左右交换；其标记值 15 不是 15% 电量。广播出现不等于设备已与本机连接，也不能仅凭同名或信号最强就合并到已配对设备。

来源：StatusUpdateDecoder.cs、PodsStatus.java、PodsStatusScanCallback.java。

2.4G 无线：接收器在线不代表耳机在线

HeadsetControl 根据 VID/PID 选择设备实现。适配要再检查设备是否可用、报文返回是否代表有效电量，以及型号的平台支持。其设备表按能力列示支持情况，不能只看到某个型号就默认所有功能可用。

来源：device_registry.cpp、逐型号能力与平台支持表。

一个相关但不宜作为首选依据的项目

Kaandonmez/BluetoothBatteryMonitor：★ 2，MIT，最近推送 2026-09-06。README 宣称支持 36 类协议。已检查的 src/BluetoothBatteryMonitor/Services/BluetoothBatteryAggregatorService.cs 实际接入 Windows PnP、BLE GATT、Apple 广播、Logitech HID 四个 provider，可以参考其分层结构，但本次没有逐一核实全部 36 类协议及设备实测。因此不把宣传覆盖数当作可直接承诺的兼容数量。

来源：聚合服务源码。另一个 muedsa/BluetoothLEBatteryMonitor 已标记 Deprecated，其关于 GATT 不能解决所有经典蓝牙耳机电量的说明仍有参考意义。

岛仔已有基础与适配建议

基于主工程提交 6156474：src/bt.rs 已枚举连接中的经典蓝牙与 BLE 设备，使用 Windows PnP 属性 {104EA319-6EE2-4701-BD47-8DDBF425BBE5}, pid 2 读取电量。连接检查约每 2 秒一次，电量约每 60 秒读取，设备变化时提前刷新。已有设备类型、缓存和退出信号，可继续复用。

src/app.rs::sync_device 主要负责连接/断开提醒；src/extras.rs 已有设备图标。原始电量只有 Option<u8>。当前分支补充来源、读取时间、连接状态与去重，监控和连接通知分别控制；通用读取不推断充电状态或分体电池。

首版：Windows + 标准 BLE

保留 PnP 电量路径，补充 GATT Battery Service。后台每 2 秒检查连接、每 60 秒刷新电量，连接变化时提前读取；慢速 GATT 请求独立运行。没有电量的设备保留连接状态。后续可引入 DeviceWatcher 与特征通知减少轮询。

扩展：逐类补充设备

优先针对实际使用的设备补齐：罗技 HID++、Galaxy Buds RFCOMM、Apple 广播、游戏耳机 USB HID。每类标注连接方式与实测型号，不宣称全品牌支持。

事件监听依据：Microsoft DeviceWatcher。此分支现已接入 Windows PnP 与标准 BLE 两条读取路径，按设备身份合并，并保留来源、读取时间与连接代次。厂商协议仍是后续适配方向。

界面与数据必须一致

  • 每个电池分量保留数值、精度、来源、采样时间与可选充电状态；有效的 0% 与未上报严格区分。
  • 连接状态与读数新鲜度分离。断开显示「已断开 · 上次读数」，过期显示「待更新」，未知显示「—」。
  • 同一物理设备的多个 Windows 节点按稳定设备身份合并；不按名称合并，不让一个来源的空值覆盖另一个来源的新鲜有效值。
  • 通用 BLE 电量特征只提供电量；没有设备证据时不推断充电、耳机盒电量或剩余可用时长。
  • 建议低电量提醒按阈值越界触发一次；恢复到阈值上方一定幅度后才重新允许提醒。过期、断开或正在充电的读数不触发。
  • 常驻最多两台，可从设备卡片固定优先显示；未固定时优先显示低电量设备。其余设备在展开卡片中查看。

代码使用边界

岛仔当前为 MIT 项目。GPL 项目在这里作为协议与行为研究参考，本次没有复制其实现进入工程。若后续直接复用或分发第三方实现，应按对应项目许可处理；btleplug 的混合来源许可也需要保留相关声明。

硬件验收范围

应覆盖一台标准 BLE 键鼠、一台经典蓝牙耳机、一个真无线耳机组和一个 2.4G 接收器设备，分别检查断开重连、睡眠恢复、无电量上报、低电量、充电、左右耳/盒子数据缺失及多来源重复识别。厂商私有协议及跨品牌兼容矩阵尚未完成硬件验收；不能据此承诺所有型号兼容。

对应设备卡片草稿：顶部常驻、侧边常驻、展开卡片。包含经典黑 / 奶油、刘海 / 胶囊，以及连接、充电、断开、过期、空状态和蓝牙关闭场景。
